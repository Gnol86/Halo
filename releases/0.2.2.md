## Explain Halo commands in Activity

Home Assistant's Activity now identifies **Halo** and the reason for its commands: detected presence, a scene's custom name, nightlight, natural light, manual control or automatic shutoff. Live editing previews and restoration also have explicit reasons.

Each dispatched command has a request entry on its target. When the light provider preserves context, the native activity detail also shows Halo and its reason as the origin of the reported state change. Adjustments and contextless device feedback retain the request entry without claiming that the light actually changed. Unchanged evaluations and skipped unavailable lights create no command entries.

Linked Home Assistant scenes record their activation on the source scene and its known light targets. Opaque scene contents are not inferred. The global feed can show both the Halo origin event and the target's request entry.

Activity and Recorder must be enabled; their filters still apply. Recorded messages use Home Assistant's configured server language: French and its regional variants, English otherwise. Custom scene names are preserved. The panel continues to follow each user's interface language. Earlier history is not reconstructed.

## Prevent false manual pauses

Some bridges, including Hue, round white temperature in mireds. Halo now tolerates that rounding when matching recent command feedback. It also accepts matching feedback when an off lamp did not expose its previous brightness or color attributes. These fixes prevent Halo's own changes from creating a manual pause, including when returning from nightlight to normal lighting.

Identified user commands and other automations keep priority. Feedback outside the expected values or response window is still treated as an external intervention.

## Installation and validation

Requires **Home Assistant 2026.10.0 or newer**. Update the Halo custom **Integration** repository through HACS and restart Home Assistant. For manual installation, use `custom_components/halo` from this release's source archive; the compiled panel is included and unchanged.

The local Python suite passes **579 tests**, including **16 Activity tests** covering native event processing, platform discovery and Recorder history, and **14 feedback regression cases**. Ruff and formatting checks pass. Existing time-based tests now freeze their clock before creating the room engine, avoiding an artificial future absence timestamp.

The release workflow requires matching version metadata, Python checks, TypeScript and panel tests, a reproducible panel build, Hassfest and HACS validation before publication. Simulated-device tests do not validate every household light integration or the final native visual presentation.

Halo remains in early development. The [default HACS catalog submission](https://github.com/hacs/default/pull/11771) is awaiting review. Publication does not install or activate this update in Home Assistant.
