## Remove manual pauses

Halo no longer pauses a room after a light change, a device report or an explicit command. This removes the feedback-detection mechanism responsible for unwanted pauses, including delayed shutoff and intermediate transition reports from Hue lights and groups.

Manual on/off commands and explicitly launched scenes are one-shot actions. Halo does not immediately undo its own explicit command, but its next normal automatic action may replace that setting or scene. To keep control, turn **Automation** off for the room; explicit commands remain available.

Live scene editing retains its temporary suspension, permissions, locking, expiry and restoration. Presence-return protection, unavailable-device handling, command attribution in native Activity and scene recursion safeguards remain in place. Light feedback updates the reported state without creating an automation pause or a command feedback loop.

## Breaking changes and migration

- Manual-pause settings, timers, status indications, diagnostics and **Resume automation** buttons are removed from the panel and Home Assistant.
- The `resume` action of `halo/command` and the `pause_until` status field are removed. Update custom clients, dashboards or automations that use them. Use the existing automation switch to enable or disable automatic control.
- Legacy `manual_pause` and `allow_off_during_pause` configuration fields are discarded on load and save, including submissions from older clients.
- Saved `pause_until`, `manual_scene_id`, `nightlight_blocked` and the obsolete `absence_confirmed` runtime values are cleared before room engines start. Rooms with automation enabled follow their normal rules as soon as the new version loads.
- Entity-registry cleanup removes only the old Halo resume buttons belonging to the integration entry. Other entities, room identifiers and unrelated settings are preserved.
- The status sensor keeps the machine value `manual` for compatibility, displayed as **Direct control** in English and **Commande directe** in French. It does not suspend automation or retain a manually selected scene.

## Validation and availability

**544 Python tests** and **96 panel tests** pass. Frozen dependency installation, Ruff, formatting and TypeScript checks pass, and the frontend bundle is rebuilt with Node.js 24. The six English/French screenshots and the **390 × 844** mobile preview are checked using simulated data, with no household instance connected.

Regression coverage includes migration of active saved pauses, legacy clients, direct commands followed by normal automation, delayed and intermediate light feedback, absence of command loops, live-editing safeguards, nightlights, presence returns and unavailable devices. Tests also cover availability recovery for linked scenes and light updates without a command context. HACS and Hassfest remain publication workflow checks. Automated tests and simulated previews do not constitute validation on every household device.

Requires **Home Assistant 2026.10.0 or newer**. This release publishes the integration package; it does not install it or restart Home Assistant. Installation, loading the new code and validation on household lights remain separate steps.
