## Recognize late light feedback without false manual pauses

Some light providers report a small final brightness or white-temperature correction long after a transition ends. Halo now continues to recognize rounding around the last commanded target. The wider range between the starting value and target still expires at the transmitted transition duration plus five seconds. Late reports cannot extend that range, accumulate drift or hide a new on/off change.

This fixes a captured household incident: a Hue light reported brightness 128, then 127 out of 255, 147.915 seconds after Halo requested 49.663% with a 60-second transition. Version 0.2.3 classified that final report as manual and paused the room for two hours. Replaying the same event against this correction recognizes it as feedback.

Identified user and external-automation commands retain priority, including small adjustments close to the target. Unidentified changes outside the target's rounding tolerance, color/effect changes and power changes still pause automation. Superseding commands, manual interventions, failures and availability changes continue to invalidate obsolete expectations. The existing rules preserving a real manual pause during a brief presence dropout are unchanged.

An unidentified physical adjustment inside the transition range, or within the final target's small rounding tolerance, remains indistinguishable from provider feedback.

## Explain detected pauses in native Activity

When a light-state change causes a pause, its native Activity now records the light name, changed values and detected origin: identified user command, identified external command or unidentified origin. An unidentified report is not presented as proof of a human action. Entries follow the Home Assistant server language, with French variants supported, and remain subject to Activity/Recorder filters.

## Installation and validation

Requires **Home Assistant 2026.10.0 or newer**. Update Halo through HACS and restart Home Assistant. Manual installations can copy `custom_components/halo` from the source archive; the compiled panel is included and unchanged.

Local validation passes **637 Python tests**, including **19 new cases**, Ruff and formatting. The exact live event was captured through Home Assistant's Events UI and replayed against both 0.2.3 and the corrected engine. Simulated tests cover delayed reports, cumulative drift, short-absence return, identified manual actions, on/off changes and native Activity attribution. Publication requires the Python, panel, HACS and Hassfest workflow checks to succeed.

The captured event establishes the specific defect and its correction; it does not establish full validation of every household device. Release publication and activation in Home Assistant are separate steps.
