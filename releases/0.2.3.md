## Prevent false manual pauses during transitions

Halo now retains each light's starting brightness and color when sending a supported transition. Some providers first report a value near the target and later report an intermediate physical value, sometimes without the original command context. These reports are now compared with the transition's original bounds, preventing them from incorrectly pausing the whole room.

The change covers natural-light adjustments, scene transitions and fading brightness during shutoff. White-temperature rounding remains tolerated, including bridges that report integer mireds. Missing starting attributes do not invent a wider transition range.

## Preserve manual control

Identified user commands and other automations still take priority, including changes that happen to fall within the expected transition range. Incompatible brightness, white temperature, colors, effects and power changes continue to trigger the room's manual pause. XY color rounding tolerance is now small enough to reject unrelated physical color changes.

Feedback recognition expires at the transmitted transition duration plus five seconds and is not extended by subsequent reports. Immediate commands and lights without transition support retain target-only matching. A new command replaces the previous expected transition; manual interventions, unavailable lamps, reconfiguration, unload and failed commands discard obsolete expectations.

For a device that provides no identifiable origin, a physical adjustment inside the same expected transition range cannot reliably be distinguished from device feedback during that bounded window.

## Installation and validation

Requires **Home Assistant 2026.10.0 or newer**. Update the Halo custom **Integration** repository through HACS and restart Home Assistant. For manual installation, copy `custom_components/halo` from this release's source archive. The compiled panel is included and unchanged.

Local validation passes **618 Python tests**, including **39 new feedback and manual-intervention cases**, plus **95 panel tests**, Ruff, formatting, TypeScript and a reproducible panel build using Node.js 24. The new regressions reproduced the transition bug and an excessive XY color tolerance before their fixes. The release workflow also requires Hassfest and HACS validation before publication.

The household inspection confirmed Halo 0.2.2 running and manual pauses following natural-light commands. Its historical brightness and color values were not recorded, so the exact household events cannot be replayed. Version 0.2.3 is verified with simulated devices; this publication does not install or activate it in Home Assistant or establish complete hardware validation.

Halo remains in early development. The [default HACS catalog submission](https://github.com/hacs/default/pull/11771) is still awaiting review.
