## Reliable presence lighting and optional manual control

**0.5.0 is a stable release.** It brings the changes from 0.5.0b1–0.5.0b3 into the standard release, with the same lighting engine and compiled panel as 0.5.0b3.

### Reliable lighting when presence returns

After an absence, a Hue group can still report a light as on. Halo previously treated the next arrival as a gradual natural-light adjustment, so a short passage could remain much too dim even when the profile requested adequate brightness.

- A genuine return after the configured absence delay restores the applicable ambience using the room's **turn-on transition**, even if a light still reports on.
- Normal lighting permission remains required. Brief absences, presence attribute updates, autonomous scenes, manual holds, live editing and disabled automation keep their existing protections.
- If a light still reports on after an accepted off command, normal policy evaluations can retry extinction after the requested fade and a short feedback grace period. Lamp reports do not immediately issue commands or repeatedly restart a running fade.
- A newer explicit command supersedes presence evaluations already waiting for a slow service, preventing an intermediate automatic flash before a manual off command.

### Optional identified manual control

- **Manual command detection remains disabled by default**, including for existing rooms. Enable **Identified commands** in a room's **Automation** tab to pause the room after a direct Halo command, an authenticated Home Assistant/API request, or an explicitly associated button.
- The default pause is **120 minutes**, adjustable from one second to seven days. Explicitly configured durations are preserved.
- Light state reports never start or renew a pause. Delayed transitions, rounding and Hue group updates are not treated as manual actions. An authenticated API request is labelled user/API; it is not proof of a human gesture or successful device execution.
- The panel shows the source, triggering light or command, deadline and **Resume**. Resuming preserves unsaved settings. English, French and Spanish are included.
- A pause ends at its original deadline, on Resume, or after a new confirmed absence that starts after the intervention. Configured automatic shutoffs remain possible during a pause. A restart restores only a valid, unexpired pause with its original deadline.
- Ordinary automation calls do not request a pause. Automations can deliberately use `halo.manual_hold` and `halo.manual_resume` with a `room_id`; starting a hold requires both identified detection and room automation to be enabled.

Associated buttons must expose Home Assistant `event` entities or use `input_button` helpers. Unconfigured physical controls and unexplained brightness or color changes are not inferred. Legacy pause fields removed in 0.3.0 remain removed; the optional feature uses separate configuration and status.

### Home Assistant sidebar access

A menu button before the Halo lotus opens the Home Assistant sidebar on narrow screens or when the sidebar is hidden in user preferences, respecting the host's kiosk and external-app exclusions. It preserves the current Halo view and unsaved settings, follows the Home Assistant theme, and has a 48 × 48 px target with keyboard focus and labels in English, French and Spanish.

### Compatibility and validation

Requires **Home Assistant 2026.10.0 or newer**. Existing profiles, brightness levels and transition durations are preserved. The compiled panel is included; no frontend build is needed for installation. Promotion from 0.5.0b3 changes release metadata and documentation only, with no additional migration or dependency change.

The unchanged 0.5.0b3 application passed **715 Python tests**, **140 frontend tests**, frozen dependency synchronization, Ruff, formatting, TypeScript and panel reproducibility under Node.js **24.22.1**. Independent review found no remaining blocking issue in the presence-lighting changes. Publication of this stable release is gated by metadata, Python, panel reproducibility, Hassfest and HACS checks.

Automated and simulated checks do not validate physical lamp behavior or establish the origin of the historical Hue feedback. No Home Assistant installation, update or restart is part of this release.
