## Identified manual commands — beta

**0.5.0b1 is a prerelease. The latest stable release remains 0.4.0.**

This beta adds optional room pauses for identified commands while keeping automation priority as the default:

- **Detection mode: Disabled by default**, for new and existing rooms.
- **Default pause duration: 120 minutes**, adjustable from one second to seven days. Explicitly configured durations are preserved.
- Enable **Identified commands** in a room's **Automation** tab to pause that room after a direct Halo command, an authenticated Home Assistant/API request, or an explicitly associated button.
- Light state reports never start or renew a pause. Delayed transitions, rounding, Hue group updates and reused state contexts are not treated as manual actions.
- The panel shows the source, triggering light or command, deadline and **Resume**. Resuming preserves unsaved configuration drafts. English, French and Spanish are included.

### Predictable pause and resume

A pause affects the whole room. It ends at its original deadline, on **Resume**, or after a new absence that starts after the intervention and satisfies both the absence delay and brief-presence-loss protection. An already established absence cannot immediately cancel a new pause.

Natural adjustments, automatic scenes and nightlight activation wait during a pause; configured automatic shutoffs remain possible. Resuming evaluates the current rules, including nightlights. Live editing and disabled automation remain separate states. A restart restores only a valid, unexpired pause with its original deadline.

Ordinary external automation calls do not request a pause. Automations can deliberately use the new `halo.manual_hold` and `halo.manual_resume` actions with a `room_id`. Starting a pause requires both identified detection and room automation to be enabled. These actions do not enable either setting.

### Detection boundaries and compatibility

Authenticated requests are labelled user/API; an API request is not proof of a human gesture or successful device execution. Permissions are checked before a request can suspend a room. Halo's own contexts, automation chains and duplicate command cascades are excluded. Newer commands, editing and Resume invalidate older authorization checks still in flight.

Associated buttons must expose Home Assistant `event` entities or use `input_button` helpers. Fresh activations are recognized; an event entity's first value without a known previous event, or after unavailability, establishes a baseline without pausing. An authenticated `input_button.press` request can identify the first press. Known groups, scenes, device, area and label targets are resolved; opaque scene effects and unconfigured physical controls are not guessed. Extended detection from unexplained brightness or color changes is not included.

Legacy pause fields and the removed `resume` command remain removed. This feature uses a separate `manual_control` configuration and `manual_hold` status; the status sensor's existing `manual` value still means **Direct control**.

Requires **Home Assistant 2026.10.0 or newer**. The compiled panel is included; no frontend build is needed for installation. Dependencies are unchanged.

### Validation

Local validation passes **695 Python tests** and **138 frontend tests**, frozen dependency synchronization, Ruff, formatting and TypeScript. Two builds under Node.js **24.21.0** produce the same panel SHA-256: `8c21c95bb8910e9cc9cac1b9f57556a463fd6e5bdeb52bacfa45d17590009e0b`. Tests confirm the disabled detection mode, 120-minute default and preservation of explicitly configured durations. Regression coverage includes delayed and reordered feedback, commands without state changes, permissions, slow calls, absence, editing, persistence and races between authorization and newer intentions. Simulated desktop/mobile checks cover localized controls and Resume while retaining a configuration draft.

Publication is gated by metadata, Python, panel reproducibility, Hassfest and HACS checks in the release workflow. Automated and simulated checks do not constitute household hardware validation. No Home Assistant installation or restart is part of this release.
