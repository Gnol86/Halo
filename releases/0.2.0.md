## Room lighting, nightlights and Home Assistant scenes

- Use an existing Home Assistant scene, including provider scenes such as Hue, directly from Halo. Linked scenes run in full through `scene.turn_on`; their conditions, priority and automatic activation permission remain configurable in Halo. Scope warnings identify known lights outside the room and incomplete scene or group information.
- Configure fixed nightlights in the room's **Ambiences** tab. After confirmed absence, Halo can keep selected room lights on while turning the others off. Nightlights follow the room's lighting permission, retain reproducible colours and effects, and respect editing, manual pauses and an explicit room-off command.
- For rooms without an illuminance sensor, choose **Always**, a daily **Time range**, or **Sun elevation** in **Automation**. Overnight ranges use Home Assistant's time zone. Solar thresholds can be shared or set separately for rising and setting sun. Normal lighting can optionally turn off when permission ends; nightlights always follow that closure.
- Show the current presence and illuminance values under their selectors, and distinguish lighting permission from measured illuminance in the room status. The panel retains Home Assistant theme colours, English/French translations and its five room tabs.

## Reliability

- Preserve existing room settings and inactive fallback choices. Existing rooms default to unrestricted lighting without a sensor and disabled nightlights. A configured illuminance sensor remains authoritative even when unavailable.
- Cancel obsolete automatic commands when presence, lighting permission, editing or a newer manual command changes the decision. Prevent repeated scene activation and preserve partial-scene inclusion when editing.
- Improve unavailable-data handling, validation, failed-save behaviour, scene permissions and recursion protection. After removing a sensor, its retained illuminance shutoff setting no longer blocks an otherwise permitted quick presence return.

## Installation and updates

Requires **Home Assistant 2026.10.0 or newer**, unchanged from 0.1.1. Update Halo through its custom **Integration** repository in HACS, then restart Home Assistant and reload the browser. For a manual installation, replace `custom_components/halo` with the folder from this release's source archive before restarting.

The compiled panel and brand images are included. Configuration is migrated with compatible defaults; no separate frontend installation is required. A linked Home Assistant scene can control equipment outside the Halo room and is never filtered like an imported copy. When the linked scene ends, Halo does not restore those outside devices.

## Validation and limits

Local checks pass: **545 Python tests**, **95 frontend tests**, Ruff, TypeScript and a reproducible panel build. Isolated Home Assistant 2026.10.0 scenarios use simulated lights, presence, illuminance and sun, including real minute-boundary scheduling. Desktop and mobile forms were checked in the native Home Assistant panel. The release workflow also requires HACS and Hassfest validation before publication.

These results do not validate household hardware or install this update. The local macOS test process still exits with code 139 after shutdown; this test-environment limitation and the precise coverage are recorded in the [fallback validation report](https://github.com/Gnol86/Halo/blob/v0.2.0/docs/QA-LIGHTING-FALLBACK-2026-10-10.md) and [broader local QA report](https://github.com/Gnol86/Halo/blob/v0.2.0/docs/QA-2026-10-10.md).

Halo remains an early development integration distributed through a HACS custom repository. This release does not submit it to the default HACS catalog or deploy it to an existing Home Assistant installation.
