# Halo panel

The integration includes a TypeScript and Lit interface. The bundle loads no libraries from a CDN. The compact layout adopted on October 9, 2026 prioritizes room control, a room list and detail view, and Home Assistant theme variables without a separate palette.

Global navigation separates **Rooms**, **Natural light profiles** and **Global settings**. A room's detail view offers **Control**, **Lights**, **Automation**, **Ambiences** and **Settings** to administrators; other users retain room control. The room list includes search, status and quick controls. It remains beside the detail view on desktop; on mobile, the list and detail view appear in sequence with a back action. Profiles are edited one at a time, with help and secondary settings in expandable sections.

**[0.5.0b2 beta — Home Assistant menu](https://github.com/Gnol86/Halo/releases/tag/v0.5.0b2):** a 48 px hamburger button before the lotus opens the host sidebar when `narrow` is true or `hass.dockedSidebar` is `always_hidden`, respecting the host's kiosk and external-app sidebar exclusions. It emits a bubbling, composed `hass-toggle-menu` event with `open: true`, without navigating inside Halo, saving settings or issuing light commands. The accessible label follows the panel language. The host supplies `narrow`; the simulator mirrors its 870 px threshold and records the event without simulating a native drawer. The 140 frontend tests cover visibility, translations, event propagation and draft preservation. A separate isolated-browser check temporarily supplied the new bundle to the existing local Home Assistant frontend and confirmed native drawer opening, without installing the bundle or modifying Home Assistant configuration. The latest stable release remains 0.4.0.

**[0.4.0 — visual profiles](https://github.com/Gnol86/Halo/releases/tag/v0.4.0):** the SVG chart combines a schematic day, a dashed sun path, a brightness curve and an opaque fill representing white temperature. The sun marker stays circular as the graph changes proportions. Two independent rows of handles adjust elevations to hundredths of a degree; value sliders use whole percentages and kelvins, with 10 px gradients and a logarithmic temperature scale. Advanced fields preserve existing exact values. New profiles use `ease_in_out`; existing profiles retain their progression type.

Unlinked morning and evening branches connect smoothly through daytime and nighttime. The preview remains schematic; the engine uses real Astral context, precise elevation interpolated between seconds, elevation-based ramps and temporal `smoothstep` joins. Unreachable thresholds are evaluated at attainable extrema, merging nodes at the same instant. A custom source without valid `next_noon` / `next_midnight` metadata uses a schematic cycle with no guarantee of alignment with real solar noon. Linked mode retains its behavior.

The preview changes only the draft and sends no commands or live-editing requests. Data and APIs remain compatible without migration; saving, discarding, conflicts and advanced-field validation retain their safeguards. Controls follow the Home Assistant theme; the fill and gradients represent light values without hardware calibration.

**0.4.0 is stable.** It uses the sources and bundle from 0.4.0b3, including the visual editor and Spanish. Only version metadata, release notes and documentation changed for that promotion. The release workflow checks metadata, Python, the panel, bundle reproducibility, Hassfest and HACS before publication.

```sh
npm ci
npm run check
npm test
npm run build
```

The build produces `custom_components/halo/frontend/halo-panel.js`, loaded by the `halo-panel` custom panel. Keep this file with the integration's distributed sources and rebuild it after frontend changes. The license for the bundled Lit libraries is kept in `custom_components/halo/frontend/LICENSE-Lit.txt`, alongside the notices in the bundle.

DOM tests use a simulated Home Assistant connection. They cover visible permissions, languages, revision-aware saving, edit conflicts, locked editing and cancellation. The redesign adds keyboard tab navigation, draft preservation across subviews, blocked navigation for invalid fields, error disclosure, focus restoration and light/dark mode changes. These tests do not replace tests on household lights.

The draft is shared across navigation. Valid input is synchronized on every `input` event; invalid numeric input stays visible and prevents leaving the subview or saving. Validation expands collapsed sections and focuses the first affected field. Discarding rebuilds the view to remove invalid input that was never stored in the model. While a draft exists, the save bar occupies permanent space at the bottom of the panel without covering the last fields. Live editing retains its own action bar and prevents navigation to another destination.

`styles.ts` and `entity-picker.ts` use Home Assistant variables for colors, states, fonts, sizes, spacing, borders, corner radii, headers and fields, with fallbacks. `hass.themes.darkMode` synchronizes `color-scheme` when provided; otherwise it remains inherited. Icons are monochrome `ha-icon` elements, and the reduced-motion preference disables visual animations and transitions.

Pickers share the `halo-entity-picker` component: case- and accent-insensitive search by name or identifier, keyboard navigation and explicit selection. Tests also cover sensor units, group information and profile/scene creation when `crypto.randomUUID` is unavailable, such as over local HTTP. The `createId` helper uses `getRandomValues` without requiring HTTPS for the panel.

`dev.html` provides a visual environment with simulated data and no connection to a real home. After building, serve the repository root with a local HTTP server and open `/frontend/dev.html`. The demo includes several rooms, states and profiles; buttons change language, role and theme (light, dark, custom), with 125% text. Previews were checked at widths of 390 and 1436 pixels. SVG icons in the simulator are for preview only; the distributed panel uses Home Assistant icons. This file is not part of the integration's distributed resources.

English is the reference catalog in `src/translations.ts`. French and Spanish use the same keys; tests verify parity and the English fallback. `fr` and `es`, including regional variants with hyphens or underscores, select their catalogs; other languages use English. Custom names are not translated. The effective Home Assistant frontend language takes precedence over a global language. Spanish, introduced in 0.4.0b3, is included in [stable 0.4.0](https://github.com/Gnol86/Halo/releases/tag/v0.4.0).

Settings use `halo/get`, `halo/subscribe` and `halo/save`. Explicit commands use `halo/command`. Live editing uses `halo/edit/begin`, `halo/edit/preview`, `halo/edit/touch` and `halo/edit/end`; the server remains responsible for permissions, validation, locking and expiration. Sessions renew every 20 seconds while the panel is connected.

In the scene editor, clicking a light row emits the public `hass-action` action with `more-info`. Home Assistant opens its own dialog; no internal component import is needed. The existing scene is previewed once before handing control to the native controls. Saving sends `capture: true` to capture actual states on the server, including effects, without resending an old preview. The `dev.html` simulator explains that this dialog requires Home Assistant and does not attempt to reproduce it.

Entity pickers remain Halo components: no public contract guaranteeing that the native picker can be loaded in this panel has been identified. The redesign adapts their styling to the theme without indirectly loading Lovelace or importing private components.

Import reads a scene's configuration through `hass.callApi`, then uses `halo/scene/import` for server-side normalization and filtering. Confirmation adds only a copy to the draft; saving uses `halo/save`. This flow never launches a scene. In the editor, inclusion checkboxes are preserved for partial scenes and sent as `capture_entities` when saving. An import response received after cancellation or navigation does not modify the draft.

After the redesign, targeted flows were also checked in an isolated Home Assistant 2026.10.0 instance with the official frontend and simulated lights: editing a partial scene with two of four lights, opening the native dialog with the "Candle" effect, cancelling to release the session, and importing two retained lights/two ignored entities into the draft before discarding it. No console errors were observed during those flows. Those local checks do not establish household deployment.
